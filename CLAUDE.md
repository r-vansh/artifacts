## What this is

art/facts: a static Astro site (artifacts.vanshrastogi.me) showcasing Vansh Rastogi's experiments. The index ships almost no JS; each experiment's code loads only when its stage scrolls into view. It is the experiments section of Vansh's main portfolio (vanshrastogi.me, hosted and running in Framer; this repo is the separate subdomain artifacts.vanshrastogi.me on GitHub Pages, built and iterated locally first; entries can link back via `inPortfolio`, and `/<slug>/play` is the embeddable stage). The parent folder `D:\Vansh Rastogi\Portfolio\Portfolio Website` is not a codebase, just a pile of portfolio assets (logos, social icons, photos, resume, case-study drafts); this repo is the only code in it. See `README.md` for the full posting guide and rules.

## Commands

```sh
npm run dev                      # http://localhost:4321
npm run build                    # astro check (types) + astro build + scripts/budget.mjs (size budget)
npm run preview
npm run poster -- <slug> [secs]  # needs a prior build; grabs poster.png from the running canvas (Chrome via CHROME_PATH)
```

Node >= 22.22 (`.nvmrc`; 22.23.2 is installed). Astro refuses to start on older Node. After changing `src/content.config.ts`, restart `npm run dev`; if pages then crash on `undefined` fields (e.g. a new field with a default), stop the server and delete `.astro/data-store.json` (a git-ignored cache) before restarting. The same cache went stale after editing several entries' `index.md` while the server ran: every page then logged `LocalImageUsedWrongly ... Received ./poster.png` and rendered only up to the first poster card (so the home page's scripts never loaded); the same fix cleared it. Stopping the shell that runs `npm run dev` can leave the server running; `npx astro dev stop` stops it. There is no test or lint script: `npm run build` is the check. CI (`ci.yml`) runs the build, then Lighthouse (`lighthouserc.json`, mobile perf >= 95). Deploy (`deploy.yml`) is manual-only (`workflow_dispatch`) to GitHub Pages; pushes never go live.

## Architecture

- **Content collection** (`src/content.config.ts`): each experiment is `src/experiments/<slug>/index.md` + `main.ts` + poster. The Zod schema is the gatekeeper: tags come from the fixed `TAGS` enum, `summary` <= 140 chars, a `poster` image or, for placeholders, a `ratio` (height / width) with an optional `fill` colour is required, `kind: external` requires `url`. Folders starting with `_` (the template) are skipped by the glob. Entry id = folder name. `gallery` (optional list of `{ image | ratio, fill }`) is extra media stacked under the entry's main block. The `src/experiments/test-*` entries are git-ignored placeholders that use solid fills.
- **Experiment contract** (`src/lib/types.ts`): `main.ts` default-exports `mount(canvas, options)` returning `{ pause, resume, stop }`. Plain modules, no framework, so the same source can be wrapped by Framer. Copy `src/experiments/_template` to start one.
- **Loader** (`src/lib/stage.ts`): one shared script for every `<Stage>`. It uses `import.meta.glob` so each `main.ts` becomes its own chunk, boots on first intersection, pauses off screen / hidden tab, shows the poster under reduced motion (opt-in "play anyway"), and falls back to the poster on error. It also stops its stages on `nav:leave` and picks up new ones on `nav:enter` (see Navigation below). Experiments should not reimplement these behaviours.
- **Entries** (`src/lib/entries.ts`): `getEntries()` sorts featured first, then newest; the running number is by oldest-first date, independent of display order (cards show it as "001"; `pad()` gives "#001"). Use it instead of calling `getCollection` directly.
- **Pages** (`src/pages`): `[slug]` (entry page), `[slug]/play` (bare stage for fullscreen/portfolio embedding, interactive kinds only), `tags/[tag]`, plus generated `rss.xml` and `llms.txt`.
- **Entry page** (`src/pages/[slug].astro`): follows Figma frame 3148:17463 (file `RaHvRAMQFzGWaKucDP940O`, Personal Portfolio). Two columns: text on the left (sticky on desktop; back chip, title, summary, tag chips, note, links), media on the right. The first media block uses the same ratio as the card on the main page (`ratioOf()`), so both show the same aspect. `ratioOf()` currently returns 1 for every entry: all cards are square, posters cropped with `object-fit: cover`, and an entry's own `ratio` is ignored for display; gallery blocks follow with a 24px gap.
- **Build config**: `trailingSlash: "never"` and `build.format: "file"` (pages emit as `slug.html`), CSS always inlined. `scripts/poster.mjs` mirrors this by serving `dist/` and appending `.html` to extensionless paths.

## Design rules (from the Figma file)

- **Colours:** only the Figma colour styles, as CSS variables in `src/styles/global.css`: `--primary`, `--primary-100..400`, `--gray-main`, `--gray-50..900` (11 grays incl. main), `--white`, `--black`. Do not add other colours or hard-coded hex values.
- **Borders:** page-level lines (contact rules, footer line, vertical guides at `--edge` from each side, stage and poster frames on entry pages) are `1px dashed var(--gray-200)`. Cards in the index grid have no border: the poster square is Gray/200 while it loads (Figma frame 3180:17526). Cards show the poster only; the title stays in the markup for screen readers.
- **Spacing:** `--gap` is a fixed 24px (entry-page media). The index grid has its own gaps from the Figma frame: 80px between columns and 160px between rows at 1440 wide, scaling down with the page (`clamp`, 24/48px at the smallest).
- **Routes:** entries open at `/<slug>`, not `/x/<slug>`.
- **Index grid** (`src/components/Grid.astro`, Figma frame 3180:17526, file `RaHvRAMQFzGWaKucDP940O`): a plain CSS grid, no JS and no scroll motion (Vansh chose this over keeping the edge-shrink motion). Five square posters across the content width (198.4px at 1440), 4 under 1200px, 3 under 900px, 2 under 600px; each card (`Card.astro`) shows the post's running number above its poster ("001", Geist Light 12px, line-height 1, Gray/900, 8px above the poster). Replaced, in this order: the Figma masonry (a column-dealing inline script), then a Fiddle.Digital-style square grid on desktop whose posts shrank into a corner at the window's edges (`scatter.ts`, deleted before it was ever committed; its history is only in `sessions.md`).
  - **First screen** (`index.astro`, 900px and wider): the "ART/facts" heading's top is at 35% of the viewport height and the grid starts at 75%, so the first posts peek in below it. The 56px in those rules is the logo header above `<main>`. The heading is `--gray-900` and the line under it `--gray-600` (the intro effect's particles take each part's own grey).
  - **Intro effect:** the heading and line above the grid collide and crumble into particles as the page scrolls; see "Intro effect" below.
- **Navigation and page transitions:** pages stay static documents. `src/lib/nav.ts` (a tiny stub on every page) lazy-loads `src/lib/barba.ts` (Barba + GSAP, one lazy chunk) on idle or first hover/touch; a click before it is ready is a normal page load. Every page's `<main>` is a Barba container (`data-barba="container"` + `data-barba-namespace`) inside `<body data-barba="wrapper">`; keep that on new pages. Barba does not run scripts, reset scroll or merge head styles, so `barba.ts` does it in `beforeEnter`/`afterEnter` (re-creates inline scripts, merges `<style>`/meta, restores scroll on back/forward, loads the new page's module scripts by URL, skips the pass Barba runs for the directly loaded page). It dispatches `nav:leave` / `nav:enter` on `document` for `stage.ts` and `intro.ts`. Files (`.xml`, `.txt`) and `/play` are never intercepted. Every swap uses one short `fade` (zero duration under reduced motion); the card-specific transitions (a poster fly-in and colour bars) were tried and dropped, so opening a post has no custom animation yet. Do not add the View Transitions API. The old WebGL shader effects are retired in `archive/transitions/` (not built or type-checked, see `archive/README.md`); `@barba/core` ships no usable types, so `src/lib/barba-core.d.ts` declares the slice we use.

## Loading animation (`src/lib/splash.ts`)

The loader is the Flow Field experiment (`src/experiments/flow-field`), mounted full screen in the `.splash` veil by `splash.ts` (viewer used while building it: `D:\Vansh Rastogi\Portfolio\Portfolio Website\Artifacts\flow-field-viewer`, port 5180). Vansh's brief (2026-10-30): use it as the loader, no parameters panel; first gone under 4 s of the click, then (same day) made to stay about 6 s. The earlier p5.js vortex is kept in `archive/splash-p5.ts` (its briefs are in `sessions.md`); `p5` is still a dependency, unused.
- **When:** an inline script at the top of `Base.astro`'s `<head>` sets `html[data-splash]` before the first paint, on the first page of a tab session (`sessionStorage` "splash"), on every load under `npm run dev`, never under reduced motion or in a background tab. `/play` doesn't use Base. Barba swaps never replay it.
- **Gate:** the experiment's own click-to-enter gate: the settled form, faint, with the paper opaque, until the first pointerdown or Enter/Space. The page under the veil is never hidden (LCP and CLS untouched), and scrolling is not locked.
- **Timing:** `splash.ts` starts a clock at that click. It mounts with `{ gui: false, revealTime: 3, exitTime: 2, gateDelay: 0.15 }`, calls `out()` (the reveal out) at `OUT` 3.7 s, and tears everything down at the latest at `LIMIT` 6 s, whatever the state (a hidden tab pauses the experiment's clock, so `out()` alone could never resolve). Measured about 5.7 s from click to `splash:done` (3.7 s before the change to 6 s). Teardown: `stop()`, remove the canvas and `data-splash`, dispatch `splash:done` (the home page holds the intro effect back until then).
- **Veil:** `data-live` hides its white `::before` (the canvas paints its own paper, and the reveal out has to open onto the page); the 5 s CSS failsafe is cancelled once `mount` has worked, since the gate may wait for a click. Do not use `data-lift` here: it sets `pointer-events: none`, so the gate click would reach links under the veil. `pointer-events: none` is set only when `out()` starts. If the module cannot start by `LATE` (4 s after navigation), the veil goes at once.
- **Panels:** `gui: false` also drops the experiment's O/R keys. The home page's dev-only intro panel (`.tune`) is hidden while `data-splash` is set.
- **Second instance:** `stage.ts` holds an experiment's boot until `splash:done` when the loader is up, so `/flow-field` as the first page does not mount a second gate on the same click.
- **Budget:** Three and GSAP land in the shared experiment chunk (144 KB gzipped, under the 200 KB WebGL limit); `splash.*` itself is 0.5 KB.
- **Verify:** headless Chrome via `playwright-core` against `npm run dev`; click, then time `splash:done`. A first run after the dependency change gave 504 "Outdated Optimize Dep" until `npx astro dev stop` and a restart.

## Intro effect (`src/lib/intro.ts`)

Home page only (`.intro[data-burst]`), every layout, skipped under reduced motion. `index.astro` loads it lazily (idle callback or first scroll; the idle load waits for the loading animation's `splash:done`), so it is a lazy chunk, not first-load page JS. Everything is driven by the eased scroll position (`glide`) until the text breaks; after that the particles run on time and physics.

- **Settings:** all in the exported `params` object, each with a slider in the dev-only panel (`src/lib/tune.ts`: `npm run dev` only, floating on the right of the home page; Copy values puts them on the clipboard in the shape of `params`, Reset restores the file's values; `index.astro` imports it behind `import.meta.env.DEV`, so the build strips it). Keep `GROUPS` in `tune.ts` in the same order as `params` with one slider per setting (37 now). The defaults are the values Vansh tuned in the panel on 2026-10-28, plus settings added after that.
- **Going down:**
  1. *Approach:* over the first `approach` of the window height the heading and the line slide together (`rush` curve) until they touch on the page's centre line (stacked on phones: they meet halfway, both centred). Over the last `blend` of it the real text crossfades (smoothstep) into the text drawn as particles, so it is all particles by the touch.
  2. *Crush:* scrolling on pushes the halves into each other over another `crush` of the window height. A particle breaks off up to `ragged` px before it reaches the centre line, never past it, so the halves never overlap. The text blurs progressively towards the centre (`soft`, `blur`).
  3. *Burst:* each broken particle pops out (`pop`, `scatter`, `squash`) into a cloud that slows at `puff`, stirred a little (`billow`, dying down at twice `puff`). The debris stays at the collision until the whole text is shredded (`shred`).
  4. *Magnet:* `hold` ms after that the pointer picks them up one by one (`stagger`, each pull building over `ramp`). They follow the pointer's path, strung out over its last `trail` ms (`taper`, `cloud`), as a force with momentum (`pull`, `fall`, `drag`, `bounce`) kept organic by eddies and uneven pulls (`wander`, `eddy`, `churn`, `fray`, `vary`).
  5. *Vanish:* the first time a particle reaches its spot by the pointer (`reach`) it fades out (`fade`) for good, so the effect ends once the swarm has caught up; the loop then stops.
- **Going up** (back above the touch): the vanished particles come out of the pointer, where it is now, one by one over `emerge` ms (each waits hidden inside it until its turn, then fades in on its way), and the text pulls each straight to its spot wherever the text is: full pull for all (no `vary`), the last `fall` px eased in over `land` ms. Once all but `LAST` (2%) are home, the particle text crossfades back into the real text over `rest` ms. Scrolling down mid-return pops them again from where they are.
- **Colour:** a particle is its own part's grey (the computed colour of the heading, `--gray-900`, or of the line, `--gray-600`; `shades` per part) and solid when it breaks off and warms to `--primary` over `warm` ms, taking its own opacity (`opacity`); on the way back it cools to the grey within `cool` px of its spot. The in-between shades are mixed from those tokens only (`SHADES` per part).
- **How it works:** the text is copied onto an offscreen canvas glyph by glyph at its laid-out positions (font size scaled for the 2x sampling) and sampled every `size` px of ink; the real text is only faded with `opacity`, so it stays in the accessibility tree. `seek()` is the physics both ways: a pull that saturates `fall` px out, damping against the velocity of the spot it follows (so tracking does not lag), extra damping near the spot, and a closing-speed cap of ω·distance + `bounce`·top speed (ω = √(pull / fall)), so `bounce` 0 never overshoots. The blur draws 16 bands (squared ease) onto the offscreen `haze` canvas and copies each with `ctx.filter = blur()` clipped to its band's box; without the clip Chrome blurred a window-sized layer (frames 7 to 21 ms). Where a canvas cannot filter (older Safari) the edge stays sharp. The loop runs only while something moves. The particles are sampled in page coordinates, so they must be re-sampled whenever the intro's layout moves: `layout()` (page width, the intro's page top, the parts' offsets) is compared on resize and whenever the loop starts. Comparing the width alone missed height-only resizes on wide screens (the intro sits at 35% of the window height), which left the particle copy off the real text, so both showed during the crossfade.
- **Measured** (headless Chrome, 1440x900): the crush ends at about 360px scrolled. With the heading at 35%, the halves touch with the heading about 90px from the top of the window and the crush ends just above the top edge (about -45px); a lower `approach` (around 0.15) or `crush` (around 0.08) keeps all of it on screen, not yet decided; particle colours match the text at the swaps (heading rgb(42,42,45), line rgb(116,116,123); within a shade both ways); going up, the real text starts fading in 1.79s after scrolling and is fully back at 2.09s (`emerge` is the biggest share); frame times are the same with and without the blur.
- **Tried and rejected by Vansh,** so do not bring back: a tween to the pointer fired by pointer events; attraction straight at the pointer (he wants the path followed); particles circling the pointer ("rotating disk"); a tidy, even trail ("a cylindrical snake"); the whole text bursting on a light touch; a break spreading out over time with carried momentum and fragments; the magnet taking debris before the text is shredded ("weird clipping"); breaking past the centre line (the halves overlapped); an exact reverse played from a recording (the particles gathered in the middle first; he wants the text to form from the pointer's side); a cloud appearing on the pointer and lingering; any abrupt colour or real-text/particle swap; a short, 5-step blur ("a rectangle of normal blur"). Matter.js was offered and not used: it handles a few hundred bodies, the text makes thousands of particles, and it adds about 25 KB gzipped.
- **To verify,** drive headless Chrome with `playwright-core` (Chrome at `C:/Program Files/Google/Chrome/Application/chrome.exe`, forward slashes) against `npm run dev`: set sliders through the panel's inputs, scroll with `scrollTo` or the wheel, read `h1.style.opacity` for the crossfades and the canvas pixels for colours. The check scripts were never saved in the repo.

## Budget (enforced by `scripts/budget.mjs`, gzipped)

HTML+inlined CSS 30 KB per page; page JS before an experiment 5 KB; one experiment 60 KB; font 30 KB. Adding a dependency or large inline asset can fail the build. Vansh treats these as a guide, not a hard rule: the site should load fast, so lazy-load anything heavy (Barba, GSAP) and raise a limit in `budget.mjs` rather than contort the design if it is justified. The script counts lazy chunks such as the Barba + GSAP one and `intro.ts` under the "experiment" limit; the loading animation's `splash.*` chunk has its own 130 KB limit (now tiny; Three is in the shared WebGL chunk).
